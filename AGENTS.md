# AGENTS.md

Notes for coding agents working on TopoMap. [README.md](README.md) explains what the app
does and how the data flows; this file covers what you need to change it safely.

## Commands

```sh
npm install
npm run dev     # Vite dev server, http://localhost:5173, live reload
npm run build   # production build; use it as the compile check
```

There is no test suite and no linter. Verify changes with a build plus a look in the
browser (see "Verifying changes").

## Stack

- Plain JavaScript ES modules, no framework, no TypeScript.
- MapLibre GL JS 6.x, maplibre-contour 0.1.x, Vite 8. `package.json` pins exact versions.
- All runtime data comes from keyless public services: Mapterhorn (elevation) and
  OpenFreeMap (vector tiles and fonts). Don't add services that need an API key without
  asking the user.

## Layout

- `index.html`: markup for the switches (top left) and the contour slider panel (right),
  and all CSS. Slider controls are generated by JS into `#contour-panel`.
- `src/main.js`: constants at the top, then the MapLibre style (inline JSON), controls,
  the switch handlers (`TOGGLES`) and the sliders.
- `src/roads-above.js`: `createRoadsAboveHighlight()`, which samples DEM tiles along roads
  and fills the `roads-above` GeoJSON source.

Style layer order, bottom to top: `background`, `hillshade`, `road-casing`,
`roads-above-edge`, `roads-above`, `road`, `contour-1`, `contour-2`, `place-labels`,
`summit-labels`.

## Pitfalls already hit

1. **MapLibre v6 is ESM-only.** Use `import * as maplibregl from 'maplibre-gl'`; there is
   no default export. Under Vite you must call `setWorkerUrl()` with the import
   `maplibre-gl/dist/maplibre-gl-worker.mjs?worker&url`. Without it the map stays blank.
2. **maplibre-contour has only a default export.** `import mlcontour from 'maplibre-contour'`,
   then `new mlcontour.DemSource(...)`. `import { DemSource }` fails at runtime.
3. **Mapterhorn 404s are normal.** Tiles exist up to z17 only where high-resolution data
   exists, and only to z12 elsewhere. MapLibre falls back to parent tiles. Keep the
   `DemSource` at `maxzoom: 12`, the highest zoom with global coverage.
4. **Use separate raster-dem sources for terrain and hillshade** (`terrain` and `dem`).
   Sharing one makes MapLibre warn and degrades the hillshade.
5. **Contours are pre-generated and the sliders only filter.** maplibre-contour only emits
   multiples of a single interval (`thresholds: { 0: CONTOUR_STEP }`). Each slider sets
   `['==', ['get', 'ele'], value]` on its layer. Regenerating tiles for every slider value
   was measured at 0.1–2 s per move, against 1–3 frames for a filter change, so keep the
   filter approach. Contour data grows roughly with 1/step: about 0.7 MB per view at
   100 m, 6–10 MB at 10 m.
6. **Keep the DEM zoom of the highlight in sync with the contours.** With `overzoom: 2`,
   a contour tile at zoom z is computed from DEM zoom `min(z − 2, 12)`. The highlight's
   `demZoom` in `main.js` mirrors that so its cut points land on the drawn blue line. If
   you change `overzoom` or `maxzoom`, change `demZoom` too.
7. **GeoJSON data must use plain objects.** Feature `properties` from `querySourceFeatures`
   have no prototype, and passing them to `setData` makes MapLibre's worker serialization
   throw `Cannot read properties of undefined (reading '_classRegistryKey')`. Copy them
   with `{ ...props }`.
8. **Style mutation timing.** An inline style object loads on the next frame, so
   `setFilter`, `setPaintProperty` and `setLayoutProperty` throw if called right after
   `new Map()`. Use `map.once('style.load', ...)`, which fires before the first frame is
   drawn, so the initial state doesn't flash. Don't gate on `isStyleLoaded()`: it also
   waits for sources.
9. **Switch state lives in the HTML.** The initial state is the checkbox's `checked`
   attribute in `index.html`, and is applied on `style.load`. `autocomplete="off"` stops
   the browser restoring a stale checked state across reloads.
10. **Line layers also stroke polygon outlines.** Road filters match `['geometry-type']`
    against both `LineString` and `MultiLineString`.
11. **OpenMapTiles road access is coarse.** The `access` field only has `'no'` (folded
    from `private` and `no`), and there's no `motor_vehicle` tag.
12. **Slider panel CSS.** `#contour-panel` has `pointer-events: none` and only the sliders
    re-enable it, so the map still pans between them. Vertical sliders use
    `writing-mode: vertical-lr; direction: rtl` (minimum at the bottom). Tick labels are
    positioned against the thumb's travel range using `--thumb`. 100 m labels are hidden
    at `max-height: 900px`, because below that they overlap.

## Verifying changes

- `npm run build` must pass.
- Run `npm run dev`, open the page, and check the console for errors. Useful views to
  navigate to (the URL hash sets the view, `#zoom/lat/lng/bearing/pitch`):
  - `#12.5/45.9763/7.6586/-120/60`: the start view (Matterhorn).
  - `#13.2/46.05/7.772/-170/50`: the Täsch–Zermatt road climbs through 1500 m, so the
    highlight should begin exactly where the blue line crosses it.
  - `#12/46.29/7.88/0/40`: the road-dense Rhône valley near Visp, a load test for the
    highlight.
- `map` is module-scoped, not on `window`. To inspect it in the browser, temporarily add
  `window.__dbg = { map };` and remove it afterwards. In v6 the per-source tile caches are
  internal, at `map.style.tileManagers[sourceId]` (`sourceCaches` in v5).
- To measure smoothness, use a `PerformanceObserver` for `longtask` entries.
  `requestAnimationFrame` timing in automated browser tabs is throttled and misleading.
- Editing `src/main.js` reloads the page through Vite. Wait for it before clicking or
  dragging in the browser.

## Conventions

- Two-space indentation, single quotes, semicolons, trailing commas.
- Tunable values are named constants at the top of `main.js`, with a comment when the
  reason isn't obvious.
- Keep the data credits: the sources supply them through their TileJSON and the map
  shows them automatically. Don't remove or hide them.
